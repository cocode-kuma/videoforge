# Harness 改造与已确认问题

修复顺序按用户要求：运行与消息缺陷、完整消息、原生 harness、多对话、结束与交付。改造前代码、配置和工程保存在项目本地 `.backups/`；服务切换前另保存运行数据。

## 1. 运行与消息缺陷

- 工具调用只有短暂状态，没有完整聊天记录：现保存参数、文件内容、结果、诊断与修订号。
- 状态长期显示“AI 正在自主制作工程”：现显示当前原生步骤、实际工具、渲染帧数和等待回答。
- 轮询可能覆盖较新的 SSE 消息，初始化可能漏事件：现合并修订号，先订阅再发送快照，并保留断线轮询。
- 停止时旧步骤仍能覆盖已停止状态，停止后立即续作可能复制正在变化的文件：现拒绝后续活动更新，等待旧运行退出后才允许续作。
- 续作漏掉未处理的用户要求：现追踪来源任务、收件记录和原生对话历史。
- 源码改变仍使用旧 bundle：记录编译输入哈希，在渲染前重新编译。
- 图片 404、坏图片被当作加载完成：检查响应状态和实际图片尺寸。
- 非零起点省略预览时长会错误越界：默认渲染剩余时间。
- Remotion 末尾静帧四舍五入可能超出最后一帧：限制到有效帧。
- 同一素材更新后界面继续显示缓存：附件带修订号，更新同一记录。
- 普通短消息被五字门槛挡住：允许正常对话消息。
- 累计 usage SSE 重复计算：旧恢复兼容循环按累计增量处理；主流程由原生会话记录记账。

## 2. 完整消息

公开回复、分析状态、提问、回答、工具调用、命令、文件内容、输出、测试、错误、原生 turn/step/request、上下文与压缩事件均可查看。长内容可展开和滚动，保存后刷新可恢复。原始内部推理和凭据不进入公开消息。

旧版保留下来的工具日志可以恢复到对话；旧版没有保存的调用名称、参数不能伪造，记录明确标记该缺失。

## 3. 原生 harness

主流程使用 DSH rc.6 的 AgentRegistry、AgentLoop、SessionStore、JSONL 持久化、检查点、请求重试、TokenMeter、工具结果整理和上下文压缩。视频操作通过原生 ToolRuntime 注册。管理员可组合可信 DSH 插件；MCP Streamable HTTP 已验证真实调用。

默认视频技术、素材、声音、技能、版本和导出工具保留，新增正常讨论结束与通用工程命令。普通沟通不强制交视频；制作模式的交付仍必须通过真实音视频检查。

## 4. 多对话

同一用户可以打开多个独立对话并执行任务。每个对话有独立工程、原生上下文与消息。只防止同一个对话启动两份冲突工作。机器渲染能力单独排队，多个 agent 不再受旧的整任务串行限制。

## 5. 结束与交付

讨论使用正常回复结束；制作使用 `submit_delivery`。没有交付的制作不会被假装标成完成。成片校验通过后计划统一完成，任务明确结束。相同源码、参数和输出的预览可复用真实渲染，重复素材更新同一记录。任务没有累计 Token、调用次数或整任务时限上限。

## 已验证

50 项回归通过；原生持久续聊、提问等待、多对话隔离、渲染排队和 MCP 调用专项通过。模拟模型驱动真实写文件、渲染错误、自动修改、声音合成和视频交付通过。真实浏览器确认重新编译与坏素材诊断；发布构建启动检查通过。未额外进行付费模型样例生成。

公开 SaaS 的脚本与命令使用隔离容器；本机可信所有者模式保留。容器环境、每个第三方插件与所有可选声音服务不等同于本次全部完成实机验收。
