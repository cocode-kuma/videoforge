# 五阶段兼容创作、技能工具与自动修复

默认已改为自主 Harness；本文描述 `VIDEOFORGE_CREATION_MODE=pipeline` 下的旧五阶段路径及服务协议。当前默认运行方式、技能接入、Remotion/Blender、配音与持续工程请看 [创作 Harness](creative-harness.md)。

新作品仍然使用一个 `main` 合成根和一条总时间线，创作改为五个专业阶段：

1. **故事**：理解用户目标、必需信息、叙事节拍和素材能力缺口。
2. **设计**：确定关键画面、主体细节、构图、字体、配色与真实素材使用。
3. **动作**：编排绝对秒数动作、转场、阅读时间和旁白。上传音乐会测量能量突变位置供编排参考，测量结果不冒充精确节拍。
4. **代码**：在统一设计与动作方案上实现完整 HTML、SVG/Canvas/WebGL、GSAP 时间线。
5. **交付**：依据代码返回真实分镜元数据与音乐事件表，不改变已确定的阶段 ID、顺序、时长和旁白。

五阶段不是固定五次 HTTP 请求：模型调用技能工具、纠正响应格式、画面评审和修复都会增加请求。所有模型请求及其返回的 token 用量均计入任务记录，并按实际模型分别计量。默认启用 low 思考，代码/修复输出预算 32768 tokens，其余阶段在思考开启时为 16384、关闭时为 8000；思考也占输出预算。可用 `VIDEOFORGE_THINKING`、`VIDEOFORGE_THINKING_EFFORT` 和 `VIDEOFORGE_MAX_OUTPUT_TOKENS` 调整。

## Skill 如何接入

### 质量瓶颈与 harness 的职责

旧链路把理解需求、视觉设计、动作、完整代码、分镜和音乐塞入同次响应。模型即便读取了大量规范，也容易把计划写得很好、画面实现却退化为标题卡或装饰。当前把这些职责拆成可留档阶段，阶段内保留工具循环；五阶段不是固定五次单向 API 调用。

Skill 解决专业知识缺口，不能代替素材工具或实际反馈。只有目录名和提示词引用不等于模型已经读取；只有技术检查通过也不等于画面符合故事。harness 提供可读取的真实参考、冻结素材与运行时、渲染诊断和实际截图，agent 根据这些信息创作及修复。未接入图片/视频生成服务时，模型仍只能使用现有素材和代码图形，不能靠 Skill 获得影像生成能力。

模型本身仍会出现结构偏差、缺失动作和视觉判断错误。授权真实样例已观察到输出截断、音乐表层级偏差、文字遮挡、主体收束落空及计划中的变形没有实现。扩大窗口和无损结构归位处理协议问题；代码和截图反馈循环处理具体作品问题。不能把这些现象全部归咎于提示词，也不能保证某个模型每次都能在两次修复内完成。

输出窗口是资源配置，不是作品字符限制。没有 HTML 字数上限；思考和内容共同占模型输出窗口，实际用量留档。达到窗口上限时最多完整重答一次，达到内容修复预算时保留失败诊断而不虚报成功。

不需要安装额外插件。沿用项目已经固定版本的 `vendor/hyperframes-skills/manifest.json`。每个阶段直接加载少量具体参考，例如故事规范、视频构图、字体规范、时间线和 GSAP 性能规则。模型还能自主调用两个原生 function tools：

- `search_skills({query})`：用英文关键词搜索参考、规则和可运行案例的路径。
- `read_skill({path,offset?,length?})`：读取返回的准确路径；超过单页长度时通过 `nextOffset` 继续。

读取前核对 manifest、路径边界和 SHA-256，不允许读取 `.env`、用户项目或任意磁盘文件。每阶段最多 12 次工具调用、8 轮响应，技能文本上限 100000 字符；四轮后停止泛读并要求完成当前阶段。输出窗口耗尽时保留诊断、将窗口扩大一倍（最多65536 tokens）并允许一次完整重答，不要求删除作品内容、最多两次格式纠错；思考上下文在工具及格式纠错轮次完整传回。只自动修正可证明的提前关闭根对象、多余代码围栏，随后仍须通过字段验证；不接受截断代码。原始技能中的安装、更新、宿主审批、固定 LEFT 和跨文件 ledger 指令不属于整片运行契约。

调用记录保存在 `<阶段>-tools.json`，实际使用的文件与哈希保存在 `skills.json`。没有固定视觉模板；具体案例用于实现参考。

## 自动修复

整片语法、lint、运行时、布局、对比度、回退 seek、可见变化、文字阅读时间、内容/视觉评审以及导出黑帧检查都可触发修复。默认最多两次，`VIDEOFORGE_MAX_REPAIRS` 可设置 0–4。旁白超过可容纳时长时先精简旁白，再生成代码，同样消耗共享修复预算。

修复携带原代码、完整方案、真实诊断，保留主体、设计与已验证内容；必须保持阶段 ID、顺序、时长和旁白。禁止靠删除文案、虚报元数据或遮挡豁免标记通过检查。环境故障、服务中断与缺少可执行文件不消耗 HTML 修复调用。

修复前后代码保存在 `repair-N-before.txt` / `repair-N-after.txt`，诊断保存在 `repair-N-diagnostic.txt`。代码档案使用文本扩展名，避免被渲染器发现为第二个合成入口。

## 画面理解与视觉评审

设置 `VIDEOFORGE_VISION_BASE_URL`、`VIDEOFORGE_VISION_API_KEY`、`VIDEOFORGE_VISION_MODEL`，接入支持图片与 function tools 的 OpenAI-compatible Chat Completions 服务。设计阶段会发送上传图片、视频抽帧和上一版截图；评审阶段发送整片不同时间点的真实截图与原始需求、方案和代码。严重的具体问题触发局部修复，主观建议不阻止导出。

未配置时仍做代码与需求审查，记录 `reviewMode: code`，不声称通过视觉评审。截图可以检查构图、信息与素材实现，不能单独证明动作连续和流畅；回退 seek 与编码检查仍然执行。

官方 `api.deepseek.com` 的 `deepseek-flash` 已支持图片输入，默认复用现有模型和凭证进行视觉评审；`VIDEOFORGE_VISION_ENABLED=false` 可关闭自动接入。其他模型或代理地址需要显式配置视觉服务，不根据名称猜测其能力。依据：[DeepSeek 官方 Vision 文档](https://api-docs.deepseek.com/guides/vision/)。

## 原创图片与短影像

设置 `VIDEOFORGE_MEDIA_API_URL` 与 `VIDEOFORGE_MEDIA_API_KEY`，接入自有或供应商适配的影像网关。设计阶段的 AI 可以自主调用 `generate_asset`，每个任务最多两个生成请求；优先复用上传或上一版素材。网关负责具体厂商模型、凭证及其费用。

请求：`POST <URL>`，Bearer 鉴权，JSON：

```json
{"kind":"image","prompt":"具体原创画面描述","purpose":"镜头中的用途"}
```

视频请求 `kind: video`，可附加 `duration`，范围 1–12 秒。

同步响应：

```json
{"status":"completed","b64_json":"base64数据"}
```

也可返回 `url`。异步响应 `{id,status:"queued"}` / `{id,status:"processing"}`，服务端对 `<URL>/<编码后id>` 发起 GET，最多 45 次，每次间隔 3 秒；最终返回上述 completed 响应。失败返回 `status: failed`。图片归一化为本地 PNG，视频须为有效 MP4 且不超过 15 秒。下载限制为公开地址和 100 MB，不把服务凭证发给素材下载地址。

生成结果冻结进本地 `assets/` 和素材清单，渲染阶段不访问外部服务。原创生成不能冒充真实城市实拍、真实产品界面或事件证据。未配置影像服务且无视觉素材时，任务会明确提示采用图形表达。

影像生成、视觉服务和 TTS 可能有独立厂商费用。任务按实际模型分别汇总 token，估算使用各模型的已配置抵扣系数；任一模型没有系数时不虚报完整估算。影像与 TTS 的独立费用不包含在模型 token 估算里。

## 配音、音乐与修改作品

恢复自动配音：配置 `VIDEOFORGE_TTS_API_URL`（可选 `VIDEOFORGE_TTS_API_KEY`），该网关接受 `{text,voice,format:"wav"}` 并返回 WAV 二进制；或者使用现有本地 Kokoro 模型和 Python 环境。未就绪时界面禁用配音，服务端在调用模型前给出明确错误，不自动安装或伪造声音。

根据真实配音长度调整阶段和动作时间，再写动画代码。交付和局部修复复用未改变的旁白音轨，不重复合成。合成音乐增加 bass、pad、bell、kick、snare、hat，可与旋律和动作编排；上传专业音乐仍可直接使用。

修改作品时保留上一版分镜、HTML、截图和本地素材，模型按修改范围更新。历史代码和视频保留在各自任务目录。原有独立分镜方法保留用于旧项目兼容，新任务不再默认调用。

## 验证

- `npm test`：技能自主调用、五阶段传递、元数据纠错、共享修复上限、视觉图片输入、声音/素材接口、旧项目兼容与服务端回归。
- `npm run test:creation`：本地模拟模型，通过真实队列、一次故意位置动画错误、自动修复、Hyperframes 检查、浏览器渲染和 FFmpeg 导出 MP4；不消费外部模型额度。
- `npm run sample:produce`：当前配置模型的真实五阶段样例，输出到 `outputs/whole-film-<时间>/`，会消费配置服务的额度。

每阶段 JSON、实际 Skill 文件、修复历史、评审和渲染报告都可用于比较质量。测试通过能证明链路运行，不能保证所有题材都达到商业成片质量；真实场景的质量仍依赖素材与所接入的服务。
