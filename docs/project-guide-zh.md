# VideoForge 项目介绍与提示词迁移说明

本文基于 2026-10-14 当前本地源码、README 和创作说明整理。代码具备某项适配能力不代表本机已配置该服务，历史验证不代表本轮重新完成实测。

## 项目做什么

Cocode Studio VideoForge 是一个通过自然语言制作代码动画视频的工作室。用户描述主题、画面、时长和声音，导演 Agent 在持续工程中寻找或制作素材、编写动画、运行真实渲染、读取错误、修改并交付 MP4 和可编辑源码。代码动画适合产品演示、品牌动态图形、科普图解和可控的风格化三维场景；影像生成依赖另行配置的网关。

它同时支持讨论和实际制作。讨论通过 finish_response 正常结束；制作需有真实成片并通过 submit_delivery。用户可以中途发送修改、停止保存、恢复任务或复用上一版工程。

## 架构与目录

| 位置 | 作用 |
| --- | --- |
| plugins/cocode-studio-ui | React 工作室与 HTTP 服务；登录、项目管理、消息、素材、预览、视频播放和下载 |
| plugins/cocode-data-store | 用户、会话、项目、素材、任务及计量存储；按用户和项目隔离 |
| plugins/cocode-director | 导演、模型调用、创作工具、队列、渲染、音频、评审与交付 |
| shared | 配置、数据契约、工作流、导出规格、日志、计费及官网接入 |
| vendor | 固定来源的 DSH、Hyperframes、Remotion 技能以及本地创作参考 |
| scripts | 启动、构建、环境诊断、运行时准备、渲染测试、源码打包和工程复现 |
| tests | 存储、接口、Agent、素材、渲染、声音、评审、认证、计量等自动测试 |
| video_projects | 用户项目、工程、任务和产物；包含私有数据，不作为普通源码交付 |
| outputs / logs | 样例输出和运行记录；不等于当前任务已通过验证 |
| deploy / runtime | 反向代理、服务部署与脚本执行容器配置 |

三个产品插件遵循 Cordis 的 name / inject / apply 契约，围绕固定版本 DSH 工作。后端使用 Node.js/TypeScript/Express，前端使用 React，构建使用 esbuild。当前 package.json 要求 Node >=22.18；README 部署建议至少 22.19。

## 默认创作链路

默认模式是 harness。harness.ts 连接产品工程和工具，native-harness.ts 连接 DSH 原生 AgentLoop、会话、检查点、重试和计量。knowledge.ts 提供多来源技能搜索和分页读取，workspace.ts 管理工程文件。

典型过程：用户 brief 和素材进入工程 → 检查环境与读取专业参考 → 保存计划与源文件 → 真实静帧和短片预览 → 按诊断修改 → 生成或导入声音 → 导出 → 评审 → 校验并交付。Agent 可以改变步骤顺序；这不是固定次数的模型请求。

旧 pipeline 模式保留故事、设计、动作、代码、交付五阶段，适合兼容原有 HTML/Hyperframes 路径。prompts.ts 是该路径的重要提示词入口；它与默认 Harness 的可操作工具和自由工程能力不同。旧文档中的调用次数、修复次数等限制不能直接用于说明默认 Harness。

## 动画与声音

| 技术 | 在项目中的用途 |
| --- | --- |
| HTML/CSS/JavaScript + GSAP | 界面、文字、产品演示及二维动态图形 |
| SVG / Canvas | 矢量图解、独立图形、逐时刻重绘 |
| Three.js / WebGL / GLSL | 浏览器三维场景、灯光、材质及着色器效果 |
| React/TypeScript + Remotion | 以帧组织多文件视频和声音 |
| Blender + Python | 真实三维工程、建模、相机、静帧和动画 |
| FFmpeg / FFprobe | 音视频转码、抽帧、合成、混音和规格检查 |
| 配音适配器 | ElevenLabs、edge-tts、MiniMax、Kokoro、WAV 网关；按配置和环境可用性选择 |

浏览器工程需支持按指定时间重建画面；Remotion 由帧号驱动。素材在渲染前落到本地，不能依赖任意外链临时加载。音轨时长来自实际音频测量，字幕时间不能冒充未经验证的逐词配音时间。

## 评审、交付与数据边界

真实渲染错误和工具失败会返回 Agent，供读取和修复。配置视觉服务后可以用实际视频抽帧评审；没有视觉服务时明确标记代码评审。静帧能检查构图和文字，无法独自证明运动流畅与音画同步，因此还有动态检查。

交付校验核对视频规格、时长、音视频流、黑帧、分镜和最新用户要求。评审证据由宿主绑定影片哈希、源码和最新要求；写假的评审文件不能绕过。已通过且没有新要求时交付，避免为可选建议无止境重渲染。

当前持久化以本地 JSON/项目目录为主，面向单 Node 服务进程。扩容需数据库和持久化队列。配置了官网 SSO、配额和积分相关实现，但上线是否可用应核对实际配置与官方接入检查表。README 中仍存在旧流程说明，阅读时优先结合 docs/creative-harness.md 和当前代码。

本机 local 执行适用于可信桌面工作区。公开多租户环境还需完整渲染 worker 隔离、权限与资源审计；runtime 容器配置不能单独证明生产隔离已完成。备份应包含 video_projects，凭证留在服务端，源码交付排除 .env、用户数据和运行时缓存。

## 本次迁移

教程原文已经存在于 vendor/creative-skills/tutorial/video-creation.md。本次核对其内容与用户提供文件一致（忽略换行差异），保留原文。

新增 vendor/creative-skills/prompt-engineering/SKILL.md，把十条技巧整理为中文创作规则和两个可复用模板。默认 Harness 的 availableSkills 同时列出指南和原文；CreativeKnowledge 自动发现该目录，无需增加外部依赖或修改固定第三方技能清单。

迁移重点：规格优先、审美具体化、主体连续、时间轴、素材真实性、三维五要素、确定取帧、声音共表、真实预览和局部修订。练习中的品牌颜色、时长、帧率和“等我确认”均保留为示例，不能覆盖用户实际请求。外部教程、网盘和技能安装链接没有自动下载或执行。

默认 Harness 新增 list_skills 和执行门禁：所有已接入的 SKILL.md 入口、教程原文和工程 skills 目录中的 Markdown 参考都必须从第一页连续读到最后一页。内置约 40 份技能入口，外部技能和新增工程参考会自动计入；专业技能引用的案例、适配器及其他参考文件仍按需读取。只看搜索摘要、跳到末页或写假的阅读记录不能放行。恢复或新一轮创作会重新建立实际阅读进度。互相冲突的风格方法按任务取舍，全读不代表全部套用。旧 pipeline 仍保持自身的阶段知识加载方式。

前置提示词 AI 使用教程、中文指南、基础创作/技术技能以及检索到的相关技能进行独立润色。所有来自工作室的新消息与中途修改先通过服务端润色再进入制作；只保存、展示和传递润色后的用户消息。润色失败不提交原文执行，取消时保留输入方便修改。默认 specMode=auto，由该 AI 根据需求决定时长、画幅、分辨率、帧率、风格和后端；文字中明确要求优先。手动指定模式保留用户选择。润色用量合并到本轮任务计量。

界面以柔光、轨道、主题标签和文字骨架动画展示正在润色，完成后展示实际润色结果，同时任务已提交；“查看创作进展”只关闭展示，不是额外确认。支持手机布局、键盘操作及减少动态效果偏好。默认 Harness 导出与交付同时检查所选帧率。

读取门禁可以证明内容确实返回给模型，不能证明模型理解或正确应用全部方法，也不保证审美质量。前置润色同样受模型能力影响，具体作品仍需真实预览和评审。

## AgentLoop 内部提示词

plugins/cocode-director/agentloop-prompts.ts 保存产品内部创作准则，直接提炼教程的十条方法：先成品后表现、具体审美、主体连续、统一时间表、真实素材、三维五要素、确定取帧、音画共表、真实预览、时间点局部修订。原文中的链接、安装和示例审批未变成内部操作指令。

native-harness.ts 在注册 DSH SystemPrompt persona 前自动加入这份准则；harness-loop.ts 在初始化或更新恢复会话的系统消息前加入同一份准则。同一系统提示词不重复添加。首次制作、后续沟通和恢复工程都会获得当前版本的内部准则，不只依赖前置润色或历史技能读取。兼容 pipeline 的 creationContract 和旧分镜 productContract 同时吸收这些方法，但仍遵循当前阶段、输出格式和宿主提供的工具。

内部准则强调对照最新需求、保存的设计与时间表、真实工程和工具证据来决定下一步。规格允许自动规划时由 AI 决定，已明确确定时保持；草稿可降低成本，正式交付维持本轮规格；讨论仍正常讨论；用户没有要求审批时不增加确认；最新评审通过后直接交付，不为可选建议无限返工。

## 怎么使用

可以直接描述需求，例如：为零基础手机观众讲清“缓存是近处保存、下次快取，也需要更新”，让 AI 自主规划成品规格。需要精确控制时，在文字中指定 20 秒或切换“手动指定规格”，选择画幅、分辨率和帧率。补充品牌素材、可用参考及关键动作，润色结果就是本轮制作输入。

修改时写“第 6–9 秒标题与图标重叠，让图标先进入再显示标题，保留其他段落”。需要审批时明确写“关键帧给我确认后再继续”；否则按现有自主流程检查和交付。

新安装流程见 DEPLOYMENT.md 和 README.md：安装依赖、配置服务端模型与 PUBLIC_ORIGIN、运行环境诊断并启动。当前默认端口是 3088。附加 Python、Blender、付费配音或素材服务按实际题材配置。

下载工程后，可按 docs/creative-harness.md 使用 scripts/render-project.ts 重新导出，通常无需再次请求模型。素材来源、代码、声音和复现信息需要一起保留。
